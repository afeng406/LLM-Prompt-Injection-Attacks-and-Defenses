# 领域边界与依赖方向

这些是职责边界，**不是要求立即创建同名包或目录**。初版文件可少，等行为增长再拆分。以 `实施方案.md` 的单轮问答与攻防评估为范围。

| 领域/位置 | 负责什么 | 不负责什么 | 对外接口或依赖 |
| --- | --- | --- | --- |
| 前端展示（Vue） | 单轮输入、资料 ID/档位选择、最终回答及状态展示 | 模型 SDK、Key、提示组装、攻击评分、读取后端文件 | 只调用 `GET /health`、`POST /api/chat` |
| 问答执行（FastAPI 后端） | 请求校验、资料白名单读取、消息组装、B0～B3 共用处理流程、原始与最终结果 | 批量用例调度、统计报表、前端布局 | 对外提供 `/api/chat`；对内部提供一个 `run_chat` 入口 |
| 模型接入（后端技术适配） | 从后端配置读取凭证，调用固定模型，将供应商响应转成问答流程需要的结果 | 业务规则、攻击成功判定、前端状态 | 只被问答执行调用；现阶段只需一个实际适配实现 |
| 实验编排（脚本与用例数据） | 冻结用例、资料 hash、`case_id × repeat_id` 夹具、四档配对、请求预算 | 复制一套问答/防御实现，修改公开 API 以传入秘密 | 用内部参数调用同一个 `run_chat`；公开 API 不暴露夹具 |
| 评估与汇总（脚本） | 读取原始/可见回答和技术状态，按冻结规则打标签，写 JSONL 与汇总 | 直接拼模型 prompt、替后端拦截输出、根据结果选择性改用例 | 消费问答结果与用例真值；后端在线请求流程不依赖评估代码 |

## 单向依赖

```text
Vue → HTTP 合同 → FastAPI 路由 → run_chat → 模型接入
                                  ↑
                         实验编排脚本
                         ↓
                         评估与 JSONL
```

- FastAPI 路由只做输入/输出适配和状态映射；业务规则不散落在路由、Vue 和评估脚本中。
- `run_chat` 是 UI 和评估共用的业务入口。内部实验夹具可由评估脚本传入，公开 HTTP 请求不能传入 canary、system 消息或任意文件路径。
- 问答执行只返回可观察结果及必要的内部元数据；攻击成功与否由评估层判定。B0～B2 对用户保留实际模型回答，B3 才执行已知 canary 输出检查。
- 资料选择与内容加载归后端；前端只提交白名单 ID。四档提示模板与防御规则各有一个实现位置，不在两端复制。
- 新增领域之间共享数据时，先明确谁拥有数据与规则，再通过小接口传递；不建立双向导入或全局“业务共享层”。

## 反过度设计检查

准备新增抽象、依赖或目录前问：当前有几个真实调用方？它隐藏了哪段稳定且重复的复杂度？删除这个抽象后，复杂度会不会散落到多个地方？如果答案不清楚，先写直接代码。课程首版不需要四套问答服务、通用工作流引擎、通用模型插件系统或跨前后端共享运行时代码。
